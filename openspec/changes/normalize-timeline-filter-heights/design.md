## Context

时间线与审核页面共用 `.toolbar` 网格。时间线页面额外渲染日期、排序和地点筛选，因此在桌面端会自动换行；其中原生 `<select multiple>` 按列表框渲染，默认高度显著大于普通输入框和单选下拉框，导致第二排高度与第一排不一致。

本次变更仅涉及 Vue 前端的筛选区结构和样式。现有 `filters.location` 数组、请求参数序列化方式、FastAPI 接口和 SQLite 数据均保持不变。

## Goals / Non-Goals

**Goals:**

- 让时间线筛选工具栏各行的收起态控件具有统一高度和垂直对齐。
- 保留地点单选、多选、已选状态回显和清空能力。
- 在现有 1100px、760px 响应式断点下保持紧凑且可操作。
- 用自动化检查覆盖控件结构、可访问标签和关键样式约束。

**Non-Goals:**

- 不调整筛选字段、默认值、查询规则或结果排序。
- 不改变审核页面的业务行为，也不重构通用表单组件体系。
- 不引入新的前端依赖、API、数据库迁移或部署配置。

## Decisions

### 使用紧凑的自定义地点多选控件

将原生常驻列表框替换为与普通输入框等高的触发控件；展开后在浮层中显示地点复选项，并直接绑定现有 `filters.location` 数组。触发控件展示“全部地点”、单个地点名或已选数量，提供清晰的选择结果。

选择该方案是因为仅强制压缩 `<select multiple>` 的 CSS 高度会让可见选项过少，并依赖 Ctrl/Command 完成多选，跨平台可用性较差。改成单选下拉则会移除现有的多地点筛选能力。

### 以时间线专用类限定尺寸规则

为地点控件及时间线工具栏增加语义化类，并在 `.toolbar` 范围内统一输入框、单选框、触发按钮的 block size、padding 和对齐。展开的地点选项面板不受固定高度约束。这样可避免全局 `input, select` 样式变化影响登录、配置或人物管理页面。

### 保持现有筛选状态和请求契约

地点复选项继续以字符串数组更新 `filters.location`，筛选按钮仍调用现有 `loadPage`。本次不改变 URL 参数格式和后端接口，减少回归范围。

### 采用现有测试工具验证

使用已有 Vitest/构建流程补充前端烟雾检查：验证时间线地点筛选使用紧凑触发控件、复选项绑定数组、关键样式类存在，并运行前端测试与构建。无需新增测试依赖；Jenkinsfile 仅在当前流水线未执行现有前端测试/构建时才同步调整。

## Risks / Trade-offs

- [自定义多选浮层需要处理展开层定位和窄屏溢出] → 将面板相对控件定位、限制最大高度并允许内部滚动；移动端改为占满网格列宽。
- [点击控件外部后浮层可能保持展开] → 优先使用原生 `<details>/<summary>` 的展开语义，避免新增全局点击监听；选择后允许用户继续多选，再手动收起。
- [固定高度可能裁剪不同平台的日期控件或文字] → 使用统一最小触控高度与 `line-height`/`box-sizing`，并通过桌面和移动断点下的浏览器烟雾验证检查。
- [审核页面共用工具栏样式] → 将新增结构限定为时间线页面，通用等高规则只规范现有单行控件，不改变审核页面字段和交互。

## Migration Plan

1. 更新筛选区标记和局部样式，并补充测试。
2. 运行前端测试、生产构建及相关后端烟雾测试。
3. 按文档影响评估更新需求规格说明书、设计说明书和 README；测试命令未变化时不修改 Jenkinsfile。
4. 部署后在时间线页面分别检查桌面端和窄屏布局，以及单地点、多地点筛选。

回滚时恢复原生地点多选框及对应样式即可；状态模型、API 和数据未迁移，无需数据回滚。

## Open Questions

无。实现阶段按现有视觉语言使用原生 Vue/HTML/CSS 完成，不引入第三方多选组件。
