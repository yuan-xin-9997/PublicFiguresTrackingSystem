## Why

当前事件审核流程让低置信、冲突或待复核事件先进入审核中心，导致采集后的事件无法直接进入时间线，也增加了日常使用中的页面和操作负担。用户希望系统更轻量：所有采集事件默认通过并直接展示，后续只在时间线中删除不需要保留的事件。

## What Changes

- 移除事件审核流程：采集、抽取、合并或导入产生的事件默认视为已通过，不再进入待审核队列。
- 删除“审核中心”页面、导航入口、页面权限项、仪表盘待审核跳转和相关审核队列交互。
- 时间线页面新增事件删除能力；管理员可在时间线卡片或事件详情中删除事件，并保留二次确认、权限控制和审计记录。
- 事件详情不再提供“通过审核/驳回”操作；事件卡片不再展示待审核状态作为核心工作流。
- 后端删除或废弃事件审核 API 的页面入口依赖，调整事件查询、统计、邮件推送和日报筛选，使采集到的事件默认进入可见时间线。
- 保留事件确认状态、置信度、证据链、来源冲突标记和人工锁定等数据质量信息；删除事件审核中心不等于移除事实质量标识。
- 同步更新 README、软件需求规格说明书、系统设计说明书、测试、冒烟脚本和 Jenkins 质量门禁。
- 非目标：本变更不重做事件抽取模型、不新增复杂编辑/合并/拆分工作台、不改变 FastAPI、Vue、SQLite 架构，也不引入新的外部服务。

## Capabilities

### New Capabilities

- `event-publication-lifecycle`: 定义事件默认通过、审核中心移除、时间线删除、权限审计、查询统计和通知筛选的事件发布生命周期。

### Modified Capabilities

无。

## Impact

- 后端：调整事件创建默认状态、事件列表/详情响应、仪表盘统计、任务结果、通知候选筛选和事件删除 API；移除或兼容审核操作入口。
- 前端：删除审核中心页面和导航；更新时间线、事件详情、仪表盘、权限管理和审计日志相关展示；新增时间线删除事件交互。
- 数据库：继续使用 SQLite；优先通过兼容迁移和保留字段处理 `review_status` 历史数据，不因本变更更换数据库或破坏既有事件、证据、邮件记录。
- 权限与安全：事件删除仅允许管理员或明确拥有事件写权限的用户执行；删除操作必须确认、写审计日志，并避免普通用户获得新增写权限。
- 通知与日报：新增事件默认可进入即时推送、定时增量推送和每日时间线邮件；发送前仍跳过已删除事件。
- 文档与测试：更新需求、设计、README、后端单元/API测试、前端测试、冒烟脚本和 Jenkins 校验，覆盖默认通过、无审核中心、时间线删除和权限拒绝场景。
