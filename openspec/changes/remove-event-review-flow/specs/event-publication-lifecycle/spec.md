## ADDED Requirements

### Requirement: 采集事件默认通过并进入时间线

系统 SHALL 将采集、人工录入分析、重分析、合并或导入产生的新事件默认标记为已通过并纳入普通时间线查询；系统 MUST 不再因为低置信度、来源冲突、敏感位置或模型校验失败而把事件放入待审核队列。

#### Scenario: 采集任务创建低置信事件
- **WHEN** 采集任务创建一个置信度低于配置阈值但结构和证据可保存的事件
- **THEN** 系统保存该事件为默认通过状态，并在时间线、人物详情和事件详情中可见

#### Scenario: 来源冲突事件默认展示
- **WHEN** 两个公开来源对同一事件存在时间或地点冲突
- **THEN** 系统保留冲突标记和证据链，并将事件展示在时间线中而不进入审核中心

#### Scenario: 模型校验失败
- **WHEN** 模型输出无法通过固定 JSON Schema 校验且系统未能生成可保存事件
- **THEN** 系统记录任务错误或拒绝该候选，但不得创建待审核事件

### Requirement: 审核中心和审核操作必须移除

系统 SHALL 从用户界面、页面权限、导航、仪表盘入口和事件详情中移除审核中心及事件通过/驳回操作；系统 MUST 不向普通用户或管理员展示待审核队列作为工作流入口。

#### Scenario: 用户查看导航
- **WHEN** 任意已登录用户打开系统主导航
- **THEN** 导航中不显示审核中心入口

#### Scenario: 管理员维护页面权限
- **WHEN** 管理员编辑普通用户可访问页面
- **THEN** 页面权限选项中不包含审核中心

#### Scenario: 管理员查看事件详情
- **WHEN** 管理员打开任一事件详情
- **THEN** 页面不显示通过审核或驳回按钮

### Requirement: 时间线必须支持管理员删除事件

系统 SHALL 在时间线卡片和事件详情中为管理员提供删除事件能力；删除操作 MUST 要求管理员权限、前端确认、后端校验并写入审计日志。

#### Scenario: 管理员删除时间线事件
- **WHEN** 管理员在时间线中确认删除一个事件
- **THEN** 系统删除或软删除该事件，将其从时间线、人物详情、地图、搜索和后续通知候选中排除，并记录审计日志

#### Scenario: 普通用户尝试删除事件
- **WHEN** 普通用户调用事件删除接口或在页面中查看事件操作
- **THEN** 系统拒绝删除请求，且页面不显示删除按钮

#### Scenario: 删除已发送通知中的事件
- **WHEN** 管理员删除一个曾经进入邮件批次或日报明细的事件
- **THEN** 历史投递记录保留事件 ID 和跳过/已删除说明，后续发送前复检必须跳过该事件

### Requirement: 事件查询和统计不得依赖待审核队列

系统 SHALL 以未删除事件作为时间线、地图、搜索、人物详情、仪表盘和任务中心统计的主要可见集合；系统 MUST 不再展示待审核数量作为核心统计或跳转。

#### Scenario: 仪表盘加载统计
- **WHEN** 用户打开仪表盘
- **THEN** 系统展示人物、来源、材料、事件和任务异常等统计，但不展示待审核事件入口

#### Scenario: 时间线筛选条件加载
- **WHEN** 用户打开时间线筛选工具栏
- **THEN** 系统不提供待审核或审核状态筛选项，并继续支持人物、日期、事件类型、确认状态、来源、地点和关键词筛选

#### Scenario: 删除事件后的统计刷新
- **WHEN** 管理员删除一个事件后刷新仪表盘和人物详情
- **THEN** 对应事件数量不再包含该事件

### Requirement: 通知和日报必须发送默认通过的未删除事件

系统 SHALL 让即时推送、定时增量推送和每日时间线邮件选择默认通过且未删除的事件；系统 MUST 在发送前复检事件是否已删除，并跳过已删除事件。

#### Scenario: 新采集事件进入即时推送
- **WHEN** 采集任务创建匹配即时推送规则的新事件
- **THEN** 系统将该事件纳入待发送批次，而不等待人工审核

#### Scenario: 新采集事件进入每日时间线邮件
- **WHEN** 新事件匹配日报规则的人物、类型和时间窗口
- **THEN** 系统将该事件纳入日报候选，而不要求审核中心通过

#### Scenario: 发送前事件被删除
- **WHEN** 邮件 Worker 发送批次前发现候选事件已被删除
- **THEN** 系统跳过该事件并记录跳过原因，且不得因为跳过影响采集任务成功状态

### Requirement: 文档、测试和交付流程必须同步移除审核流程

系统 SHALL 更新 README、软件需求规格说明书、系统设计说明书、自动化测试、冒烟测试和 Jenkins 校验，使交付材料与默认通过和时间线删除流程一致。

#### Scenario: 冒烟测试执行
- **WHEN** 冒烟测试运行采集、查看时间线和删除事件流程
- **THEN** 测试不再执行审核中心通过/驳回步骤，并验证管理员可以从时间线删除事件

#### Scenario: 文档查阅
- **WHEN** 用户查阅 README、需求规格说明书或系统设计说明书
- **THEN** 文档描述事件默认通过、无审核中心、管理员在时间线删除事件，并保留质量标识和证据链说明
