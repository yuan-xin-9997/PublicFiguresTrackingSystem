## REMOVED Requirements

### Requirement: 推送规则支持即时与定时增量模式
**Reason**: 推送管理页面下线"推送规则"模块，即时推送与定时增量汇总两种投递模式整体移除，由单一的"动态推送"（每日时间线邮件演进）替代。
**Migration**: 已创建的推送规则数据随 `notification_rules` 等表一并删除，不补发历史；需要持续推送的用户应改用"动态推送"规则按人物、事件类型、信息源维度配置定时汇总。

### Requirement: 定时窗口按事件入库高水位增量切分
**Reason**: 定时增量按入库高水位游标切分窗口的能力随定时增量功能下线而移除。
**Migration**: 动态推送改为按事件发生时间的日历窗口（昨天自然日 / 滚动 N 小时）汇总，不再使用入库高水位游标；历史 `scheduled_notification_*` 运行记录丢弃。

### Requirement: 规则生命周期不得隐式回溯
**Reason**: 游标重置与停用期间不补发等规则生命周期约束是定时增量专属逻辑，随功能下线移除。
**Migration**: 动态推送不存在入库游标概念；其启用前不补跑的约束由 `dynamic-push` 规格的补跑规则承接。

### Requirement: 运行创建与游标推进具备事务性和幂等性
**Reason**: 定时增量运行创建与游标推进的事务幂等机制随功能下线移除。
**Migration**: 动态推送运行的事务幂等（同规则同业务日期幂等）由 `dynamic-push` 规格承接。

### Requirement: 调度使用北京时间日历时刻并可恢复
**Reason**: 定时增量专属的北京时间日历调度与重启只补最近一期行为随功能下线移除；该调度语义由动态推送继承。
**Migration**: 动态推送规格包含等价的北京时间日历调度与重启只补最近一期要求。

### Requirement: 定时运行筛选、排序和空窗口行为确定
**Reason**: 定时增量运行的筛选、排序与空窗口行为随功能下线移除。
**Migration**: 动态推送规格包含候选筛选（排除审核驳回）、稳定排序与空窗口行为要求。

### Requirement: 定时增量邮件复用持久化重试能力
**Reason**: 定时增量专属的批次重试入口随功能下线移除；底层 SMTP 持久化重试能力为动态推送与历史投递重试共享，予以保留。
**Migration**: 动态推送规格承接 SMTP 配置复用、邮件分片、稳定 `Message-ID`、Worker 轮询、指数退避、最大尝试次数与失败批次重试要求。

### Requirement: 管理界面、权限和审计完整呈现定时增量状态
**Reason**: 定时增量规则 CRUD、窗口预览、立即汇总、运行列表/详情与批次重试的界面与 API 随功能下线移除。
**Migration**: 动态推送规格承接等价的管理界面、`notifications` 页面权限只读脱敏、管理员写操作与审计摘要要求。

### Requirement: 配置和部署保持安全兼容
**Reason**: 定时增量专属配置项（默认发送时刻、轮询周期等）随功能下线移除。
**Migration**: 动态推送规格承接配置可覆盖、增量部署不覆盖 `app.json`、凭证脱敏与旧配置安全忽略要求；`scheduled_incremental` 配置段在升级时被安全忽略。
