## Context

当前采集链路先通过集中 WebFetch 的 `generic.article` 得到标题和正文，再由 `collectors.py` 做通用清洗与文章有效性检查，最后由 `extractor.py` 的本地规则或外部模型生成事件。现有 `_primary_person_id` 以“人物首次出现位置是否早于首个动作词”为核心，不能把真正的动作主体与背景提及区分开；外部模型结果虽再次调用该函数校验，仍继承相同缺陷。中国日报网尚未加入站点适配，首页/栏目文本被压平成长字符串时可能越过通用标题边界并进入分析。

变更跨越采集、抽取、维护 API、任务日志和测试，但保持 FastAPI + Vue + SQLite 架构，不引入新的 NLP、数据库或抓取依赖。集中 WebFetch 仍负责网络访问、缓存、重试、限流和 SSRF 防护；PFTS 只负责业务层正文质量与人物归属判断。

## Goals / Non-Goals

**Goals:**

- 以保守、可解释、可单元测试的规则证明人物是事件动作或言论的主体，不能仅凭正文提及建立归属。
- 让本地抽取、外部模型成功路径和外部模型失败回退路径共享同一归属验证器。
- 清除中国日报文章中的页头、首页标题、栏目导航、推荐阅读和页尾，并在入库前拒绝聚合页。
- 允许管理员先预览再修复已有错误归属，保护人工锁定事件和仍有有效证据的事件。
- 在任务中心与审计日志中给出候选、拒绝、修复、保留和失败计数，便于验收与回滚。

**Non-Goals:**

- 不实现通用中文依存句法分析或引入大模型作为唯一正确性门槛。
- 不保证自动识别省略主语、跨段复杂指代等全部语言现象；证据不足时宁可不生成自动事件。
- 不自动改写人工审核锁定的事件，不删除原始合法文章，不改变事件类型、登录方式、页面权限模型或北京时间展示。
- 不修改集中 WebFetch 服务本身，也不绕过其安全策略直接抓取目标站点。

## Decisions

### 1. 用“谓词锚点 + 主体窗口”替代文档级首次提及

抽取器先按段落、句号及分号切分证据，再在单个子句中定位行程/言论谓词。候选人物必须满足以下之一：

- 姓名或别名位于同一子句的谓词前主体窗口内，且在人物与谓词之间没有明确引出另一个动作主体的结构；
- 句首为“他/她”加谓词，且上一相邻句存在唯一、显式、已验证的主体，且未跨越段落、标题、日期列表或导航边界；
- 标题和正文首句均明确以同一人物为主体；标题本身只用于增强证据，不能在正文无主体时单独兜底。

每个谓词分别绑定主体，不再使用“文档第一个动作词”选择一个人物覆盖整句。对于 `other`，必须存在目标人物的显式主体和可识别的事实谓词；仅出现姓名不再生成兜底事件。选择保守规则而非引入分词/句法库，是因为当前部署要求依赖少、需支持离线本地规则，且本次反例可以由可解释的局部规则覆盖。代价是部分复杂句会被送入人工补录或不产生事件。

### 2. 统一候选事件后置验证

新增独立的主体证据验证函数，输入为目标人物、事件类型、证据片段及必要的相邻句上下文，输出“接受/拒绝 + 原因”。本地抽取在构造事件前调用；外部模型响应通过 Schema/证据包含校验后再次调用；本地回退自然复用同一入口。

外部模型的 `person_id`、摘要或解释不能覆盖证据判断。验证失败的候选不写入 `timeline_events`，并在模型运行/任务日志中聚合记录拒绝原因。采用共享后置验证而非只增强提示词，是因为提示词不能保证所有模型和回退路径一致。

### 3. 将中国日报适配放在通用正文管线之后、入库校验之前

`clean_article_content` 继续先做通用标题边界、电头和页尾处理，再按规范化 host 对 `chinadaily.com.cn` 及其子域应用站点规则：

- 从唯一文章标题、明确正文容器输出或首个可信正文段落开始；
- 移除中国日报首页/频道标题、语言/客户端入口、导航、分享/字号控件；
- 在“相关阅读、推荐阅读、编辑/责编、版权”等边界停止；
- 折叠重复标题，但保留正文中的真实引语和段落内容。

清洗后统一执行文章有效性检查：标题异常、URL/标题呈现首页栏目、正文过短、导航标记密集或标题/正文重复污染时拒绝。WebFetch `generic.article` 正常结果与本地 HTML 清洗降级结果走同一规则。选择 PFTS 站点适配而非修改集中服务，是因为这些规则属于本项目的业务质量门槛，同时避免影响 WebFetch 的其他消费者。

### 4. 存量修复采用 dry-run、证据级验证和事务提交

新增管理员维护操作，默认/显式支持 `dry_run=true`。扫描范围限于自动分析产生、`human_locked=0` 的事件证据：

1. 用当前人物、原始文档和新版验证器逐条重验事件证据；
2. dry-run 返回受影响人物、材料、证据、将删除的孤立事件和保留事件计数及有限样例；
3. 执行时只删除无效证据；事件仍有其他有效证据则保留，完全失去证据且未人工锁定时才删除；
4. 对中国日报污染材料先重新清洗并判断，聚合页按现有清理语义删除，合法文章保留原始记录并可重新分析；
5. 整个批次在 SQLite 事务中完成，失败回滚；重复运行结果幂等。

维护操作要求管理员权限，并写审计日志。任务中心复用现有运行/日志模型展示计数；若现有 `collection_tasks` 外键结构不适合独立维护任务，则维护 API 的结构化结果与审计日志为最低实现，不为此强行改变数据库模型。

### 5. 配置与安全边界保持现状

网络请求继续读取 `collector.webfetch_base_url`、`collector.webfetch_api_key_env`、超时、缓存和直连降级配置；密钥只从环境变量读取，系统配置页面继续脱敏。站点域名集合和 HTML 语义标记属于解析器代码常量，不是环境连接信息。不会新增硬编码 IP、端口、用户名、密码或绝对路径，也不会扩大私网/外域访问范围。

## Risks / Trade-offs

- [规则更保守导致少量真实事件漏报] → 用明确反例/正例测试约束边界，将拒绝原因记入任务日志，并允许从原始材料人工审核或后续重分析。
- [“他/她”跨句承接错误] → 只允许相邻句、唯一显式主体且不跨段落/列表边界；不满足即拒绝。
- [中国日报页面模板变化] → 通用质量校验作为第二道防线，站点规则保持小而集中，并用真实结构的固定夹具测试。
- [存量修复误删共享事件] → 先删无效证据，只有无有效证据且未锁定的孤立事件才删；执行前 dry-run，事务失败自动回滚。
- [数据库规模使全量重验耗时] → 分页读取、限制单事务批次或按来源/人物过滤，API 返回计数；不在普通请求路径同步全库扫描。
- [外部模型与本地规则产生不同候选] → 共享后置验证保证最低归属标准一致，但不强求候选数量完全相同。

## Migration Plan

1. 先部署纯代码规则、站点清洗和测试，不自动触发存量删除。
2. 在测试环境对用户给出的反例和中国日报样本运行采集/抽取回归，确认普通站点无明显回归。
3. 生产部署后由管理员执行 dry-run，保存计数与样例；确认后再执行修复。
4. 修复完成后重新运行受影响来源的采集/分析任务，并从习近平时间线、中国日报来源和任务日志抽样验收。
5. 若规则回归，回滚应用版本即可停止新的过滤；存量修复前备份 SQLite 数据文件。已删除记录通过该备份恢复，不依赖逆向生成。

## Open Questions

- 实现阶段需用当前中国日报实际页面样本确认正文开始/结束标记；若不同子域模板差异较大，拆成同一域族下的多个小型适配器。
- 需在 dry-run 后由管理员确认生产修复范围（全量、指定人物或指定来源）；API 设计应预留人物/来源过滤参数。
